# 分阶段执行指南

使用方法：每阶段建立一份 [执行记录](templates.md)，把下述产物链接进去。阶段状态仅取 not_started / running / blocked / passed；blocked 说明具体外部依赖，不能用它代替尚未完成的实现。

## 角色与环境

| 角色 | 负责决定什么 |
| --- | --- |
| 产品/业务负责人 | 什么记忆有用、哪些不该保存、试点范围、质量底线 |
| 实现负责人 | 数据/接口实现、自动测试、缺陷修复、真实命令 |
| 运行负责人 | 环境、密钥、实验总预算、数据期限、告警和恢复 |
| 评审者 | 检查期望、错误样例和放行证据；尽量不只依赖实现者自评 |

允许一人兼任。合成开发环境、产品内部环境和未来生产环境分离，禁止拿生产副本作为便利的默认测试数据。

## M0：把决定转成可工作的任务

前置：本套文档与 RFC 可读，目标仓库位置明确。无需模型凭据或真实用户数据。

操作：

1. 登记已决定项：首个产品试点、无旧 Mirror 兼容、PostgreSQL、SDK 优先、embedding 可选。
2. 逐项阅读 R01–R15，特别确认“关闭、纠正、删除、过期、历史查询”的差别。
3. 建立目标仓库分支及文档索引；保留可追溯历史后再处理旧文件，不在产品中新建第二套正式内核。
4. 冻结第一轮接口与状态名，建立 C01–C20 测试清单和合成数据命名约定。
5. 填写当前负责人、环境名、下一项任务 T01。预算和真实数据期限允许暂空，因为当前不用它们。

交付：T00 记录、设计决策清单、M1 任务顺序。退出：确定性实现没有待猜测的核心语义。发现歧义时用具体输入/预期输出解决，不再广泛比较开源框架。

## M1：构建可靠内核

前置：M0 通过；隔离 PostgreSQL 与开发权限可用。

操作：

1. 按 T01–T07 实现；先身份/事务，再任务，再召回，最后控制与恢复闭环。
2. 建立唯一推荐启动方式，并将实测命令填入 [命令登记](templates.md)。所有本地命令默认使用合成测试环境。
3. 跑通六步示例：用户 U1 表达技术回答偏好 → 等待 ready → 新 session 召回 → 更改偏好 → explain → forget 并验证。
4. 用 U2 和第二 app 执行同样查询，确认没有串数据；在处理中执行撤销、进程终止和重复投递。
5. 在隔离数据库测试 source 到期、恢复旧备份及重放删除，不使用系统时钟跳变影响其他应用。
6. 留存 commit、schema 版本、测试结果和失败修复记录；不上传原始数据库或凭据作为证据。

交付：可运行内核、实际命令、C01–C15/C18 的适用报告、确定性示例。退出：任何隔离、删除、幂等、撤销失败必须修复；模型质量不属于本阶段阻塞因素。

失败处理：数据库不可用则不返回 accepted；已有 job 失败保持可追踪状态；恢复只对测试范围操作。不要以加模型、加 Redis 或加缓存绕过未解决的一致性缺陷。

## M2：产品内部测试与成本校准

前置：M1 通过；先合成数据。任何付费调用之前填实验总预算；真实测试者数据之前填授权、目的地和保留 profile。

操作：

1. 完成 T08，产品先启用 shadow。继续由现有路径生成回复，Mirror 结果仅供对照；计量 shadow 带来的额外成本。
2. 建立固定开发/留出数据集；同一条完整会话只属于一个集合，避免拆消息造成泄漏。
3. 完成 T09，比较无长期记忆、原始会话检索、现有产品、Mirror 固定规则；无法公平对比的差异明确记录。
4. 使用 [验证指南](validation.md) 的小规模配置实验产出质量、时延和成本表；通过预登记条件后才进入 active_internal。
5. active_internal 只作用于测试名单和独立会话；每次回复记录实际使用的 memory ID/版本，不默认保存整段 Prompt。
6. 完成 T10，用模拟限流/重试和负载回放测试关闸、冷却、恢复；选定带版本的默认 profile。
7. 邀请非作者执行接入示例，记录卡点并修正 T11 文档/工具。

交付：产品 adapter、基线报告、样例误差分析、候选 profile、接入体验记录。退出：质量门槛与成本门槛均满足，授权/删除回归通过。失败保留 shadow 或 off，不进入真实内部对话接管。

## M3：内部验收与运行准备

前置：M2 已有通过候选、固定版本、内部测试范围和运行负责人。

操作：

1. 固定发布候选，执行留出集与通用契约；不得看完失败后改阈值追认本轮通过。
2. 在多个 session 验证：临时要求不污染长期偏好、旧计划不当成现在、用户纠正立即阻断旧版本。
3. 用模拟时钟覆盖休眠/到期；真实连续使用观察不能被模拟测试完全替代，两种证据分开报告。
4. 演练模型故障、worker 失联、数据库不可用、撤销乱序与删除超时；按 [运行手册](operations.md) 处置。
5. 演练 profile 回退、schema 兼容检查、备份恢复和完整测试批次清理。
6. 汇总放行记录：可用场景、已知限制、成本范围、告警联系人、停止条件。记录是否仅内部可用。

交付：T12–T13 报告及内部验收结论。退出：所有强制项通过且运行路径可执行。生产接管需另行明确发布范围，不能把本指南视为生产变更授权。

## M4：第二产品接入

前置：首个产品验收通过；新产品有接入方与自己的授权来源。

操作：

1. 分配独立 app/用途和数据存储隔离边界；不复制首个产品用户记忆。
2. 建立新产品最小样例：长期语言/风格偏好、某篇文章的临时要求、偏好纠正与删除。
3. 复用 application 用例，增加领域规则和呈现；将所有核心改动单独列出理由。
4. 执行 C01–C20 适用项，重新测试成本曲线；不照搬首个产品参数。
5. 重跑已有回归，确认第二产品没有破坏原有行为。

交付：跨产品接入报告、复用/改动清单、独立 profile。退出：两个产品均有证据。此时再决定哪些内部接口值得公开为插件契约。

## 各阶段不通过时

工程契约失败：修复后重跑对应边界及必要回归。质量失败：按提取、形成、检索、呈现定位，不一次替换全套组件。成本失败：在质量底线内减少不必要处理并重新测量。授权、预算或真实数据条件缺失：继续合成数据工作，暂停对应外部操作。

本轮具体下一动作是 T00/T01；无需先确定付费模型或真实用户的长期保留天数。
